## 三、規則那一側做了什麼

**重要的做法**：沒有去改文字版的檔案，因為使用者還在玩文字版。HD-2D 的規則另外寫在 `zg/hd/`，只借用文字版的資料表（`zg/data.py`）和狀態結構（`zg/state.py`）。之後也請維持，不要為了 HD-2D 去改 `zg/hd/` 以外的 `zg/*.py`。

**使用者說過新版的數值不一定要跟原版一樣**（2026-11-18）。所以數值以原版為起點，可以照新設計調。

| 檔案 | 內容 |
|---|---|
| `zg/hd/rules.py` | 共用的數值：走路的時間、聲音半徑、距離帶 |
| `zg/hd/battle.py` | 戰鬥。每個單位輪流行動、四段距離帶、前後排、十一種指令、七種環境指令、隊友不聽話和性格發作、中途加入的敵人 |
| `zg/hd/containers.py` | 把房間的物資分進容器。住宅區八間房排好了，其他地區用通用的三個 |
| `zg/hd/session.py` | 畫面和規則之間唯一的窗口。探索、搜索、戰鬥、存讀檔的指令 |
| `zg/hd/bridge.py` | 程式進入點：一行 JSON 進、一行 JSON 出。實際開成子程序跑過 |
| `tests/test_hd.py` | 38 項測試，包含隨機亂按 120 場 |
| `docs/RULES_BRIDGE.md` | 溝通格式的完整說明，Godot 那一側照這份寫 |

**還沒做的**（也列在 `docs/RULES_BRIDGE.md` 第八節）：

- 技能指令：重擊、包紮、翻找、警戒。
- 環境指令裡的「拿起來用」（椅子、滅火器）和「翻過去」。
- 探索動作：貼著門聽、躲藏、設定會響的東西、推家具擋門。
- 過夜、加固、交談、收人、製作、吃東西：目前用 `text` 指令借用文字版，回來的只有文字，沒有結構化的事件。
- 每天早上的存檔點、死亡後的處理。
- 平衡。沒有人玩過。隨機亂按的結果是贏 37、逃 51、死 32，只能證明規則不會壞。

**我注意到、還沒處理的事**：

- 文字版的情報系統會檢查 `room.loot`。HD-2D 版第一次進房間時把 `room.loot` 搬進容器，之後情報的真假判斷會看不到東西。還沒修。
- 文字版街道上生成的少量物資（約五件）在文字版本來就拿不到，HD-2D 版也沒有給街道容器。要不要讓街道上的機車、垃圾桶可以翻，沒有問過使用者。
- 存檔沒有存「戰鬥進行中」的狀態，戰鬥中不能存檔。

## 五、房子骨架

2026-11-18 做了第一版，能走、能上下樓，家具大多是素色方塊佔位。截圖：`docs/handoff/shots/house_1f_2026-11-18.png`、`house_2f_…`、`house_3f_…`。

### 檔案

| 檔案 | 內容 |
|---|---|
| `hd2d/kit.gd` | 共用工具（貼圖、方塊家具、立牌、小人、環境、輸入、截圖），全部是 static。原本在 `main.gd` 裡，搬出來了 |
| `hd2d/house.gd` | 房子模式，約 950 行，前 230 行是資料表（`ROOMS`、`DOORS`、`STAIRS`、`PLACES`） |
| `hd2d/main.gd` | 原本的測試房間。看到 `--house` 就把 `house.gd` 叫起來 |
| `hd2d/tools/house_walk_test.gd` | 不需要顯示卡的走路檢查 |
| `hd2d/shot.ps1` | 多了 `-House`、`-At`、`-Noise`、`-Wide` |

`kit.gd.uid`、`house.gd.uid` 還沒產生。第一次用編輯器開專案時會出現，要一起提交。

### 怎麼啟動

```
C:\tools\hd2d\godot\Godot_v4.7.2-stable_win64.exe --path hd2d -- --house
```

WASD 或方向鍵走，Shift 跑，可以點地板。參數：`--at=房間`（alley、bedroom、living、kitchen、garage、kids、hall、master、bath、attic）、`--wide`（拉遠看整層）、`--noise`（顯示跑步的聲音半徑）。

截圖（`-Out` 要給完整路徑）：

```
powershell -ExecutionPolicy Bypass -File hd2d\shot.ps1 -House -At kitchen -Out C:\完整路徑\a.png
```

走路檢查，最後印 `WALK TEST OK` 就是通過：

```
C:\tools\hd2d\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path hd2d --script res://tools/house_walk_test.gd
```

### 格局

每間深度都是 6（z 從 -3 到 3），牆高 3.2，樓層高 3.375（十四級階梯）。

| 樓層 | 由左到右（x 範圍） |
|---|---|
| 一樓 | 臥室 -15～-9、客廳 -9～1、廚房 1～7、車庫 7～15 |
| 二樓 | 小孩房 -15～-9、樓梯廳 -9～1、主臥 1～7、浴室 7～12 |
| 三樓 | 閣樓 -9～1，其餘是屋頂 |

- 巷子在房子前面，z 從 3 到 8，左右到 ±17 用圍牆擋住。
- 大門在客廳前牆 x = -7。其餘的門都開在左右隔牆上、z = 0.6。廚房通車庫的門鎖著。
- 兩段樓梯都在 x -5.8～-0.925。第一段貼客廳後牆往右上到二樓；第二段在樓梯廳往左上到閣樓。

### 做了的

- 房間、樓板、牆、門洞、屋頂、巷子、鄰居。
- 門走近會自己開；車庫門打不開，會顯示「車庫的門鎖著。」
- 樓梯走上去高度會變、會換樓層。
- 只顯示玩家所在樓層以下；進屋後該層前牆換成一截矮牆。鏡頭跟著人走。
- 閣樓是暗的，有一盞跟著玩家的小燈。
- 家具有圖用圖，沒圖放 `docs/FIRST_BUILD.md` 尺寸的素色方塊。美術交圖後把檔案放進 `hd2d/art/furniture/` 就會自動換上，不用改程式。
- 走路和跑步的聲音半徑會顯示成一個圈；巷子和廚房各有一隻行屍，在半徑內就朝聲音的位置走。

### 沒做的

- 屋頂和牆的淡出，現在是瞬間切換。
- 按鍵開關門、門的聲音。
- 行屍的尋路（只會直線走，會卡牆）、聲音被牆擋住、行屍上下樓、碰到玩家之後的任何事。
- 車庫進不去。
- 夜晚氣氛沒有調，亮度是估的。
- 陳水木現在是站在臥室裡，不是躲在床底下。
- 還沒有接規則：房子裡的東西不能翻，沒有時間、沒有戰鬥。

### 驗證過的（換電腦前，Claude 親自跑過）

- 四種啟動方式（預設、`--lineup`、`--house`、`--house --at=attic --noise`）headless 都沒有錯誤訊息。
- 走路檢查九項全過：進大門、上二樓、上閣樓、走回二樓、穿過兩扇門到浴室、撞鎖著的車庫門。
- 看過一樓和二樓的全景截圖（軟體算圖），格局看得懂。

### 沒驗證的

- 實際用鍵盤走的手感、鏡頭跟隨、門自動開關的時機、換樓層那一瞬間的畫面。這台電腦看不到。
- 廚房、臥室、二樓各房、閣樓的近景沒有截圖，只在全景裡看過。
- 聲音半徑的圈、行屍朝聲音走，只跑過程式，沒看過畫面。
- 滑鼠點地板在房子模式沒有測。
- 整棟同時存在時的流暢度。

### 要請使用者決定的

- **格局**：房子是寬 30、深 6 的一長條，每層的房間左右排開，不像一般的透天厝。這是為了鏡頭固定朝後看而排的。另外多了一間文字版沒有的「二樓樓梯廳」。要不要改，還沒問過使用者。
- **隔牆上的門**關著時幾乎是側面對著鏡頭，不好認。
- **汽車**照清單的尺寸是橫著放的，和鐵捲門的方向不合，車庫因此加寬到 8。

### 已知的問題

- `--wide` 全景左右兩頭會被切掉。
- 佔位的素色方塊很簡陋，巷子的正面只有牆、暗窗和鐵捲門。
