# 給美術總監的交接說明

這份是寫給擔任美術總監的 ChatGPT 看的。你透過 GitHub 讀到這個倉庫，請先讀完這一頁，再照「先讀這些」的順序看其他文件。

## 這個專案是什麼

《末日第十四天》：一個十四天的回合制殭屍求生遊戲，舞台是台灣的虛構河港小城「臨汐市」。文字版（Python）已經完成且可玩，現在要做成 HD-2D 風格的 PC 版：像素角色立在 3D 場景裡，有打光、景深、光暈，探索時可以上下左右自由走動，戰鬥是橫向站位的回合制。引擎是 Godot 4.7。

## 三方分工

| 誰 | 負責 | 不碰 |
|---|---|---|
| 使用者 | 所有決定。操作繪圖 AI 生圖，挑選，最後說了算 | |
| ChatGPT（美術總監） | 風格定調與一致性、提示詞、審圖、素材清單與進度追蹤、場景與介面的視覺方向 | 程式碼（`zg/`、`hd2d/*.gd`、`hd2d/tools/`、`tests/`） |
| Claude（工程與技術美術） | 遊戲規則、Godot 場景與程式、把圖匯入遊戲（去背、切格、縮放）、在引擎裡打光、截圖回報實際效果 | 風格決定。覺得風格有問題會提出來，但由美術總監和使用者決定 |

兩個 AI 不能直接對話，所有溝通都透過這個倉庫裡的檔案，見最後一節。

## 先讀這些

1. `docs/WORLD_BIBLE.md`：世界觀、所有角色的故事與形象、風格規範、提示詞。**第十一章是目前生效的角色圖規格。**
2. `docs/ART_TRACKER.md`：每個角色每組圖的進度。這份由你維護。
3. `docs/handoff/eng_to_art.md`：工程這邊給你的最新狀況和問題。
4. `docs/GAME_DESIGN_HD2D.md`：HD-2D 版的玩法設計。第二節是城市地圖和要畫的套件清單，第五節是戰鬥，會決定家具怎麼畫。
5. `docs/HD2D_PLAN.md`：整個改版的計畫、決定和階段。看「現況」和「架構決定」兩節就夠。

`DESIGN.md` 是文字版的完整規則，很長，需要查某個機制時再看。

## 已經定案的事（請不要推翻，要改請先問使用者）

- **場景角色的風格**：使用者用繪圖 AI 生成的大格像素風。三到四頭身、粗黑外框、格子明顯（1024 寬的圖上一格約 16 像素）。基準圖是使用者手上的三張：許晏、沈以美、符婕。
- **立繪的風格**：柔和的插畫風設定圖，淺灰底，正面加四分之三側面。許晏、沈以美已有（`hd2d/art/concept/`）。
- **每個角色只留一個代表色**，在暗的場景裡一眼認得出來。代表色表在 `WORLD_BIBLE.md` 第八章。
- **提示詞不寫任何遊戲或畫師的名字**，用描述的方式講風格。
- **符婕**是使用者自己小說裡的角色，長相、個性、來歷以使用者的設定為準，不能改。但在這個遊戲裡，她只是一個在找爸爸的女孩：小說裡那些複雜的背景不在遊戲裡交代，也不做成任何機制。
- **場景只放現代都市裡有的東西**（2026-11-18 使用者決定）。背景是當代的台灣城市，出事才幾天。奇幻或中世紀角色扮演遊戲裡常見的擺設一律不用：木箱、木桶、寶箱、火把、油燈、鐵柵地牢、石砌牆。要堆東西就用紙箱、塑膠籃、棧板、貨架；要有光就用日光燈、檯燈、手電筒、手機螢幕、停電時的蠟燭。判斷方法：這個東西出現在現在的便利商店、公寓、醫院、警局裡會不會奇怪。
- **東西大部分是新的**（2026-11-18 使用者決定）。故事只有十四天，兩週不會讓東西生鏽、褪色、剝落、長青苔、爬藤蔓，建築不會變廢墟。家電、家具、招牌、車子、貨架上的商品都跟出事前一樣新。災難的痕跡是「亂」和「髒」，不是「舊」：翻倒的、打破的、匆忙丟下的、新鮮的血跡和泥腳印、薄薄一層灰、沒倒的垃圾。提示詞裡請避開 abandoned、ruined、rusty、weathered、overgrown、decayed、post-apocalyptic 這類字，繪圖 AI 看到就會把整個畫面做舊。原本就舊的東西（老公寓的鐵窗）可以舊。
- 平台只有 PC。使用者不喜歡虛擬搖桿，手機版已放棄。

## 引擎這邊的硬性要求

這些不是美感問題，是不照做就放不進遊戲：

1. **背景用純洋紅 `#FF00FF`**。白底會讓白衣白鞋被一起去掉，黑底會讓深色衣服和頭髮融進背景切不出來。角色身上有洋紅色時改用純綠 `#00FF00`。
2. **不要邊緣光、發光、地上的影子**。光和影子由引擎打。圖上先畫了光，進場景後光源在另一邊就會穿幫。
3. **所有角色同樣的頭身比、同樣的大小、同樣粗細的像素格**。
4. **站姿自然、雙手垂下、腳踩同一條地平線**。戰鬥姿勢留給戰鬥組。
5. **一張圖裡的每個姿勢等距、不重疊**，不然程式切不開。
6. **不要文字、標籤、邊框**。
7. **給原圖，不要截圖**。有得選就用 PNG。

目前已知的一個限制：繪圖 AI 畫的像素風，格子其實不整齊，邊緣沒有落在固定格線上。匯入時會統一縮到固定尺寸，但成品不會像手繪像素那樣完全乾淨。如果你知道哪個工具或設定能出真正對齊格線的像素圖，請告訴使用者。

## 每個角色要的四組圖

| 組 | 內容 | 檔名 |
|---|---|---|
| A 轉身圖 | 站姿三個方向：正面、側面朝右、背面，排成一列 | `<代號>_turn.png` |
| B 走路 | 側面走、朝鏡頭走、背對鏡頭走，各一張，每張四格排成一列 | `<代號>_walk_side.png`、`<代號>_walk_front.png`、`<代號>_walk_back.png` |
| C 戰鬥 | 備戰、蓄力、出手、受擊、倒地，排成一列，面朝左 | `<代號>_battle.png` |
| D 立繪 | 插畫風設定圖 | `<代號>_concept.png` |

角色代號：`hero`（許晏）、`mei`、`qiang`、`chen`、`kai`、`lin`、`jie`、`fang`、`bang`、`fujie`、`sgt`、`sister`、`hai`、`major`、`walker`、`runner`、`bloater`、`raider`、`soldier`。

誰需要哪幾組、提示詞範本，都在 `WORLD_BIBLE.md` 第十一章。

**順序**：先做三個基準角色的 A 轉身圖，確認繪圖 AI 換方向時能維持同一個人。過了再做 B，再做 C，然後才擴到其他角色。走路的連續格是繪圖 AI 最不擅長的，請特別留意，生不好要早點說，工程這邊有退路（用程式讓角色上下晃加抬腳）。

## 審圖時請看這幾點

- 跟基準圖放在一起，像不像同一個畫家畫的：頭身比、外框粗細、格子大小、上色方式。
- 代表色有沒有守住。
- 換方向或換姿勢後，還是不是同一個人：髮型、衣服細節、配件、身高。
- 職業和身分看不看得出來（對照 `WORLD_BIBLE.md` 的形象描述）。
- 上面七條硬性要求有沒有違反。
- 縮小到遊戲裡的大小後還認不認得出來。

通過的圖放進 `hd2d/art/inbox/`，並在 `ART_TRACKER.md` 把那一格改成「待匯入」。

## 之後需要你定方向的東西

現在只有角色在動，下面這些都還沒有方向，請你和使用者討論後寫進 `WORLD_BIBLE.md`：

- **場景的畫法**。地板、牆、家具現在是純色方塊。要用什麼風格的貼圖，跟大格像素角色的格子大小怎麼搭。擺設只能是現代都市的東西（見上面「已經定案的事」）。
- **感染者的設計**。三種的形象描述有了，但還沒有任何圖。
- **介面**。選單、對話框、戰鬥指令、狀態列的視覺風格。
- **物品圖示**。武器、食物、藥品、工具，約四十種。
- **戰鬥時的畫面**。戰鬥在原本的房間裡開打（2026-11-18 使用者決定），不需要另外的戰鬥背景。要定的是指令選單、行動順序列、距離標示疊在場景上的樣子。
- **音樂與音效的方向**。每個地區的情緒已寫在 `WORLD_BIBLE.md` 第七章。
